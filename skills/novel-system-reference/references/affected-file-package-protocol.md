# 受影响文件包协议

本协议定义返工场景里的最小推进单位：**受影响文件包**。

返工不按单章推进，也不按整本书推进，而是按真实污染面推进。

## 定义

受影响文件包是一组需要一起分析、一起改、一起确认的文件集合。

一个文件包通常包含：
- 一组章节文件
- 对应章节级证据或审计
- 对应 `plot/` 文件
- 对应人物卡 / 关系卡
- 对应 `context.md` 位点
- 必要时对应 `summary.md` 摘要位点

## 为什么不是单章

因为很多返工并不是线性影响：
- 改一章可能牵动更早章节
- 改一章可能牵动更晚章节
- 改一章可能先影响人物卡，再反过来影响 plot

所以主单位必须是“文件包”，而不是“章节”。

## 最小字段

一个文件包至少要能表达：
- 包名
- 涉及的章节
- 涉及的人物卡
- 涉及的 `plot/` 文件
- 涉及的 `context.md` / `summary.md` 位点
- 当前状态
- 是否已确认
- 是否依赖其他包

## 跨包依赖

文件包之间允许存在跨包依赖。

例如：
- 包 B 依赖包 A 的人物关系先改完
- 包 C 依赖包 B 的剧情节点先稳定

协议必须允许记录这类**跨包依赖**，避免系统误以为所有包都能独立推进。

## 状态建议

文件包可采用类似以下状态：
- 待分析
- 待改写
- 待确认
- 已确认
- 已合并
- 已废弃

## 推进原则

- 先分析，再改写
- 同包内文件一起看，不拆散确认
- 未确认前不回灌主线
- 整体返工范围确认完成后，再进入主线合并

# `context.md` 协议

`context.md` 是单本书工作区里的**共享决策日志**。

它用于记录多轮讨论后已经拍板的关键结论、尚未解决的冲突、覆盖旧资料的依据，以及仍需用户确认的问题，方便大纲、剧情、人物三个领域技能在同一份上下文上连续工作。

## 定位

`context.md` 记录的是**决策状态**，不是完整聊天记录，也不是第二份 `summary.md`。

- `summary.md`：高层稳定状态与当前结论，方便快速回看。
- `context.md`：多轮确认过程中的关键决策、冲突、覆盖历史与待确认问题。
- 领域文件（`outline/`、`plot/`、`characters/`、`canon/`）：最终的长期资料落点。

## 什么时候写

出现以下情况时，优先更新 `context.md`：

- 用户刚刚明确确认了一个关键结论。
- 新结论覆盖了旧结论，需要说明依据。
- 两步确认之间出现冲突，但暂时不能直接裁定。
- 某个问题必须等用户拍板，才能继续稳定回写。

## 什么时候不写

以下内容不要写进 `context.md`：

- 完整聊天逐字稿。
- 纯脑暴阶段的大量备选灵感。
- 已经稳定落盘、且没有冲突或待确认价值的细节长文。
- 章节细表、长人物卡、长篇世界观设定。

这些内容应分别进入 `inbox/`、`plot/`、`characters/`、`canon/` 等更窄的目录。

## 推荐区块

```text
# 项目上下文

## 会话目标
## 当前有效结论
## 最近确认
## 冲突清单
## 待用户确认
## 影响范围
## 覆盖历史
```

### 会话目标

只写当前这一轮或最近连续几轮讨论在解决什么，例如“确定主旨与第一卷方向”。

### 当前有效结论

只保留仍然生效、且会影响后续工作的关键结论。这里是领域技能进入工作前的第一阅读入口。

### 最近确认

追加记录最近一次拍板的高价值结论，便于回溯“现在为什么是这样”。

### 冲突清单

记录尚未解决、且会影响任务走向的冲突。每条冲突都应尽量写清：
- 冲突双方是什么
- 来自哪一步或哪份资料
- 为什么不能直接覆盖
- 下一步需要用户确认什么

### 待用户确认

只保留真正阻塞后续稳定回写的问题。优先记录高杠杆问题，不堆积琐碎小问答。

### 影响范围

记录本次确认会影响哪些文件，例如 `summary.md`、`outline/volumes.md`、`plot/mainline.md`、`characters/index.md`。

### 覆盖历史

当新结论明确替代旧结论时，在这里留下一条简短记录，说明：
- 新结论覆盖了什么旧结论
- 覆盖依据是什么
- 哪些文件已同步更新

## 单条记录模板

可按下面的最小格式记录：

```markdown
- 日期：YYYY-MM-DD
- 触发步骤：例如“确认第一卷方向”
- 结论：一句话写清本次拍板内容
- 证据等级：已确认事实 / 强推断 / 待确认 / 建议
- 来源：用户本轮确认 / `summary.md` / `plot/mainline.md` / 其他明确来源
- 影响文件：`summary.md`、`outline/volumes.md`
- 覆盖旧结论：否 / 是（写清被覆盖项）
- 状态：生效 / 待确认 / 已解决冲突 / 已废弃
```

不要求每次都写成长段解释，但必须让后续技能看得懂“这条结论现在是否有效”。

## 冲突处理顺序

1. 先检查用户本轮最新明确指令能否直接覆盖旧结论。
2. 若能覆盖，写入“覆盖历史”，并同步更新受影响文件。
3. 若不能直接覆盖，先把冲突写入 `context.md` 的“冲突清单”。
4. 然后只问一个最小必要问题，等用户拍板后再继续。

## 回写顺序

领域技能在处理关键确认时，推荐按这个顺序执行：

1. 更新 `context.md`
2. 更新最窄、最匹配的领域文件
3. 只把高层结果摘要同步到 `summary.md`

这样可以避免冲突过程污染 `summary.md`，也能保留覆盖依据。

## 初始模板建议

新建书籍工作区时，`context.md` 可以先放一个空模板：

```markdown
# 项目上下文

## 会话目标

待定。

## 当前有效结论

待补充。

## 最近确认

- 暂无。

## 冲突清单

- 暂无。

## 待用户确认

- 暂无。

## 影响范围

待补充。

## 覆盖历史

- 暂无。
```

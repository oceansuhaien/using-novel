# `context.md` 协议

`context.md` 是单本书工作区里的**共享决策日志**。记录多轮讨论后已经拍板的关键结论、尚未解决的冲突、覆盖旧资料的依据，以及仍需用户确认的问题，方便大纲、剧情、人物、场景系列技能在同一份上下文上连续工作。

## 定位

`context.md` 记录的是**决策状态**，不是完整聊天记录，也不是第二份 `summary.md`。

- `summary.md`：高层稳定状态与当前结论，方便快速回看。
- `context.md`：多轮确认过程中的关键决策、冲突、覆盖历史与待确认问题。
- 领域文件（`outline/`、`plot/`、`characters/`、`canon/`）：最终的长期资料落点。

作者级偏好、跨书复用经验走 `preference-memory-protocol.md`，不属于 `context.md` 主体协议。

已落盘正文的返工走 `rewrite-branch-protocol.md`——但**阶段 C 之后**，这一协议被 `novel-draft-system` 的版本链替代：每次改写自然落草稿快照，rollback 即分支回退；不再需要手工维护改稿分支目录。

## 与正文执行审计的边界（更新）

`novel-draft-system` 已经在每个版本快照头部记录结构化元数据（`kind`、`from_ver`、`slice_ref`、`author_note`、`forced`、`timestamp`），这就是正文执行审计的载体。

- **不再**让 AI 手写 `chapters/notes/scene-audit-*.md` 一份额外审计文件。
- 需要"这版为什么这样写"的信息 → 直接读快照头 yaml。
- 只有审计产出的稳定结论（影响后续技能的）才摘要写入 `context.md`。

## 什么时候写

- 用户刚明确确认了一个关键结论。
- 新结论覆盖了旧结论，需要说明依据。
- 两步确认之间出现冲突，但暂时不能裁定。
- 某个问题必须等用户拍板才能继续稳定回写。

## 什么时候不写

- 完整聊天逐字稿。
- 纯脑暴阶段的大量备选灵感 → `inbox/`。
- 已稳定落盘、无冲突的细节长文 → 对应领域目录。
- 章节细表、长人物卡、长世界观 → 对应领域目录。
- 单次正文生成的详细审计 → 由快照 yaml 头承载，不写这里。

## 推荐区块

```text
# 项目上下文

## 会话目标
## 当前有效结论
## 最近确认
## 冲突清单
## 待用户确认
## 影响范围
## 覆盖历史
```

- **会话目标**：当前 1-3 轮讨论在解决什么。
- **当前有效结论**：仍然生效、影响后续工作的关键结论。领域技能进入工作前的第一阅读入口。
- **最近确认**：最近一次拍板的高价值结论。
- **冲突清单**：尚未解决、影响走向的冲突。每条写清：冲突双方 / 来自哪一步 / 为什么不能直接覆盖 / 下一步需要用户确认什么。
- **待用户确认**：真正阻塞后续稳定回写的问题。只记高杠杆问题。
- **影响范围**：本次确认会影响哪些文件。
- **覆盖历史**：新结论覆盖旧结论时记 1 条：覆盖了什么 / 依据 / 已同步哪些文件。

## 单条记录模板

```markdown
- 日期：YYYY-MM-DD
- 触发步骤：例如 "确认第一卷方向"
- 结论：一句话写清本次拍板内容
- 证据等级：已确认事实 / 强推断 / 待确认 / 建议
- 来源：用户本轮确认 / `summary.md` / `plot/mainline.md` / 其他明确来源
- 影响文件：`summary.md`、`outline/volumes.md`
- 覆盖旧结论：否 / 是（写清被覆盖项）
- 状态：生效 / 待确认 / 已解决冲突 / 已废弃
```

不要求每次都写成长段解释，但要让后续技能看得懂"这条结论现在是否有效"。

## 冲突处理顺序

1. 先检查用户本轮最新明确指令能否直接覆盖旧结论。
2. 能覆盖 → 写入"覆盖历史"并同步更新受影响文件。
3. 不能直接覆盖 → 先把冲突写入 `context.md` 的"冲突清单"。
4. 只问一个最小必要问题，等用户拍板后再继续。

## 回写顺序

领域技能处理关键确认时按此顺序：

1. 更新 `context.md`（走草稿协议工作台）。
2. 更新最窄最匹配的领域文件（走草稿协议工作台）。
3. 只把高层结果摘要同步到 `summary.md`（走草稿协议工作台）。
4. 用户确认后由作者触发 `draft-finalize.sh` 对应资产。

避免冲突过程污染 `summary.md`，也保留覆盖依据。

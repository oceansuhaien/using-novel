# 场景扩写

## 作用

在当前场景工作台基础上**加料**：补内心戏、环境描写、动作神态、感官细节、关系暗示。**不改主干事件**。

若本轮请求触及事件/决定/结构 → 提示切到 `novel-scene-rewrite`。

## 输入规则

1. `drafts/chapters/<scene>.md`（当前版本）。
2. 需要知道角色状态以补内心戏时，可读 `drafts/characters/<id>/state.md` 的"当前情绪 / 当前目标"两段。
3. 需要知道环境细节时，可读当前场景的 `drafts/chapters/<scene>.slice.yaml` 的 `env.ambient`。
4. 不读整张 plot、整张人物卡、非在场角色资料。

## 边界红线（与 polish 一致）

- 禁止改事件顺序、角色决定、场景结构。
- 禁止加新场景或删既有场景。
- 允许：加描写段、加内心独白、加动作/神态承接、加环境感官、加关系暗示。
- 允许字数大幅增长（扩写本职）但上限为原稿的 1.5 倍；超过 → 改走 rewrite。

## 工作流

1. 读工作台正文。
2. 识别请求具体方向：
   - **内心戏** → 在 pov 角色行动前后补 1-2 段，不堆纯情绪词，要落到身体反应 + 念头变化。
   - **环境描写** → 从 slice.env.ambient 里挑 1-3 个元素，用于服务情绪/节奏/张力。
   - **动作神态** → 在关键对白前后补动作托底，让对白不悬空。
   - **感官细节** → 视觉/听觉/嗅觉/触觉，但一段只主打一个感官。
3. 产出修订版。
4. `draft-write.sh chapters/<scene> expand <tmp-file> --note "<扩写类型：内心/环境/动作/感官>"`。

## 硬约束

- 字数上限：原稿 × 1.5。超过 → 停下，提示作者"这已超出 expand 范围，建议 rewrite"。
- 每处新增必须服务**本段既定意图**；新增内容不能改变事件结果。
- 内心戏不替作者替角色拍板。例如 state.md 里写"警觉但未确定"，扩写时不能升级为"已确定"。
- 环境描写从 slice.env.ambient 出发，不凭空发明新地点/新物件（那是 rewrite 或 plan-slice 的职责）。
- 不把扩写变成说教、作者腔评论。

## 回报形态

产出 + 一句 summary："本版扩写重点：<在哪里加了什么>"。1-3 点。

## 按需读取

- `../novel-scene-polish/references/tomato-style-checklist.md` — 白描落点、感官细节、对白托底检查（扩写也适用）。

## 不做的事

- 不改事件/决定/结构（rewrite）。
- 不压句去 AI 味（polish）。
- 不回写 state.md（finalize 才触发）。
- 不凭空发明新环境元素。
- 不把扩写做成重写。

## 自检

- 事件结果是否和原稿一致？
- 新增的内心戏/描写是否能从 state.md / slice 推出？没有越权定案？
- 字数是否在原稿 × 1.5 以内？
- 有没有为了加字而堆空泛形容？
- 新增环境是否服务情绪/节奏/张力，而不是纯装饰？

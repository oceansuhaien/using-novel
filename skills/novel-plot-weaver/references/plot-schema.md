# 剧情资料结构

用于决定已确认剧情材料应写入 `plot/` 的哪个文件。

## 目录契约

```text
plot/
  mainline.md
  hidden-threads.md
  foreshadowing.md
  beats.md
  volume-hooks.md
```

## 文件职责

### `mainline.md`

只存稳定主线信息：

- 故事阶段目标。
- 可见冲突。
- 对抗力量。
- 主线推进链。
- 重大不可逆转折。

不要把每个脑暴分支都倒进这里。

### `hidden-threads.md`

存放：

- 隐藏动机。
- 延迟揭示。
- 可见剧情下方的压力线。
- 每条暗线最终如何撞上主线。

每条暗线优先使用：

- 暗线名称。
- 当前隐藏状态。
- 揭示触发条件。
- 揭示窗口。
- 对主线的影响。

### `foreshadowing.md`

存放：

- 埋下什么。
- 埋在哪里。
- 准备什么未来回收。
- 回收前必须满足什么条件。
- 是否已经回收。

优先表格化，避免长段散文。

### `beats.md`

存放：

- 主要剧情节点。
- 升级点。
- 反转。
- 后果。
- 节点之间的因果承接。

当用户讨论“接下来发生什么”多于“故事整体意味着什么”时，用这个文件。

### `volume-hooks.md`

存放：

- 当前卷目标。
- 卷末爆点。
- 交给下一卷的未解问题。
- 下一阶段钩子承诺。

## 路由规则

- 稳定高层概览仍属于 `summary.md`。
- 临时、未确认可能性属于 `inbox/`。
- 章节级观察属于 `chapters/notes/`。
- 如果结论被未确认人物事实卡住，标注依赖，不要升级成剧情 canon。

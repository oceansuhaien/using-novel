# 剧情资料结构

用于决定已确认剧情材料应写入 `plot/` 的哪个文件，以及各输出形态的推荐区块。

## 目录契约

```text
plot/
  mainline.md
  hidden-threads.md
  foreshadowing.md
  beats.md
  volume-hooks.md
```

## 文件职责

### `mainline.md`

只存稳定主线：

- 故事阶段目标
- 可见冲突
- 对抗力量
- 主线推进链
- 重大不可逆转折

不要把每个脑暴分支都倒进这里。

### `hidden-threads.md`

每条暗线优先使用：暗线名称 / 当前隐藏状态 / 揭示触发条件 / 揭示窗口 / 对主线的影响。

### `foreshadowing.md`

优先表格化，避免长段散文：埋下什么 / 埋在哪里 / 准备回收什么 / 回收前条件 / 是否已回收。

### `beats.md`

主要剧情节点 / 升级点 / 反转 / 后果 / 节点之间的因果承接。用户讨论"接下来发生什么"多于"故事整体意味着什么"时，用这个文件。

### `volume-hooks.md`

当前卷目标 / 卷末爆点 / 交给下一卷的未解问题 / 下一阶段钩子承诺。

## 路由规则

- 稳定高层概览仍属于 `summary.md`。
- 临时、未确认可能性 → `inbox/`。
- 章节级观察 → `chapters/notes/`。
- 结论被未确认人物事实卡住时，标注依赖，不要升级成剧情 canon。

## 输出形态模板

### 当前可确认的剧情结构

按需输出：

- 当前讨论对象
- 服务的主线或暗线
- 阶段目标
- 核心冲突
- 推进链条
- 可确认剧情节点
- 可确认伏笔或回收点
- 对连载节奏的作用
- 当前依据（来自哪个文件或片段）
- 待确认问题

### 可讨论强化项

只有在事实与缺口已分清后再给有限建议，且必须标注为"建议"：

- 哪个节点不够有钩子
- 哪条暗线可以更晚揭示
- 哪个伏笔现在埋会更值
- 哪个反转需要更早铺垫
- 哪个阶段目标太虚，需要改成可执行目标

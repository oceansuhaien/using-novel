# 小说人物卡教练

## 共享规则

需要目录、证据等级、跨文档同步或回写边界时，使用 `novel-driver:novel-system-reference`。

本技能只负责人设提炼、人物卡、关系卡、人物总表、人物弧线和与人物直接绑定的规则。

## 主职责

把零散人物信息整理成能服务写作的人物资料：

- 先抽取证据，再组织角色信息。
- 区分已确认事实、强推断、待确认和建议。
- 找出角色最能制造剧情的矛盾点。
- 用户确认后把人物资料写入 `characters/`。
- 人物变化清楚影响剧情、大纲或 canon 时，同步更新对应文件。

不要为了让卡片看起来完整，就擅自补出整套童年、动机、秘密或人物弧光。

## 何时使用

优先处理这些请求：

- 做人设卡、人物卡、角色设定卡。
- 根据已有小说架构资料整理某个角色。
- 从大纲、章节或灵感里提炼人物信息。
- 梳理角色身份、动机、关系、戏剧功能。
- 用户强调"别乱编""先和我确认"。
- 讨论自然延伸到关系卡、人物总表、弧线、秘密或人物绑定规则。

不要强行接管：

- 纯世界观、总大纲、卷纲、力量体系整理。
- 用户明确只想自由脑暴，不要求严谨归档。
- 纯组织/地点/规则设定，且暂不服务某个角色塑造。

## 输入优先级

1. 用户本轮明确给出的新信息。
2. 用户点名参考的文件或片段。
3. `context.md` 中仍然生效的结论、冲突清单与待用户确认项。
4. `summary.md`。
5. `characters/`、`chapters/`、`outline/`、`plot/`、`canon/` 中的相关文件。
6. 用户临时粘贴的聊天补充或灵感。

多源冲突时，先判断本轮确认方向是否覆盖旧结论。能覆盖就同步更新并回写 `context.md`；不能判断且会影响任务意图时，先列冲突写入 `context.md`，再提问。

## 工作流

1. 确认目标角色是谁。
2. 先读取 `context.md`、`summary.md` 与角色相关资料，再收集与角色有关的明确材料。
3. 区分已确认事实、强推断、待确认和建议（证据等级见 `novel-driver:novel-system-reference`）。
4. 判断是否存在关键缺口。
5. 关键缺口存在时，先问少量高杠杆问题（默认一轮只推进一个最关键问题）。
6. 缺口解决后，再产出人物卡草案。
7. 讨论自然扩展到关系、弧线、秘密或绑定规则时，可补充对应卡片。
8. 用户确认后，先更新 `context.md`，再回写项目文件。

## 关键缺口

出现以下缺口时，不要假装人物卡已经定稿：

- 核心身份不清。
- 核心动机、欲望或执念不清。
- 与主角或关键人物的关系定位不清。
- 与角色行为直接绑定的规则不清（组织命令、仪式、力量、信仰如何改写角色选择）。
- 文件落盘路径不清（该进 `summary.md`、`characters/cards/`、`characters/relationships/` 还是暂存 `inbox/`）。

可问 1–3 个高杠杆问题，例如：

- "他对主角到底是保护对象、潜在敌人，还是已经在局中？"
- "她当前显性目标是求生、求爱、求权，还是求真相？"
- "这个角色最关键的矛盾是表里不一、立场撕裂，还是欲望与能力不匹配？"
- "这次信息只进单角色卡，还是已经足够同步到人物总表？"

## 严谨原则

- **事实与推断分层**：任何人物信息都要归入已确认事实 / 强推断 / 待确认 / 建议之一。组织规则、服从规则、关系驱动同样分层处理。
- **少而准地提问**：先问行动引擎、核心欲望、关键关系，再问枝节；不要机械补全表格。
- **不越界**：关系卡、人物总表、弧线、秘密表、强绑定规则卡仍属本技能；纯世界观、纯场景编排、纯卷纲规划不属本技能。

## 输出形态

默认输出"已确认人物卡 + 可讨论强化项"两段，详细区块模板见 `references/character-schema.md`。

- **已确认人物卡**：按需使用区块（身份、动机、关系、矛盾、优势弱点、戏剧功能、证据来源、待确认问题等）；"当前证据来源"尽量写清来自哪个文件或片段。
- **可讨论强化项**：只有在事实与缺口分清后再给 2–4 个有价值方向，必须标注"建议 / 备选"。
- **相关卡片**（按需）：关系卡、人物总表、人物弧线卡、秘密表 / 信息差表、强绑定规则卡——只在服务人物塑造时生成，不机械全套输出。

## 回写规则

用户确认后再写文件：

- 单角色深度卡 → `characters/cards/<角色名称>.md`。
- 多角色关系 → `characters/relationships/`。
- 人物总表和索引摘要 → `characters/index.md`。
- 高层稳定结论精简同步到 `summary.md`。
- 未确认问题 → `inbox/` 或卡片的"待确认"区。
- 章节观察不足以升格为稳定设定时，留在 `chapters/notes/` 或 `chapters/extracts/`。

角色名称未最终确定时，不要抢先创建正式角色文件；先把命名问题列为待确认。

## 多材料处理

- 优先提取稳定信息，不被单一章节的临时表现误导。
- 区分角色一时表现与长期特征。
- 章节表现和设定文件冲突时，判断本轮确认方向是否已经覆盖旧设定。
- 角色在章节里明显出现新立场但摘要未更新时，列为"已观察变化，是否升格为正式设定待确认"。
- `context.md`、`summary.md` 与角色资料彼此冲突时，先把冲突写入 `context.md`，再只问一个最小必要问题。

## 参考文件

按需读取：

- `references/character-schema.md`：人物卡、关系卡、人物总表、弧线、秘密、强绑定规则卡的目录契约、区块模板与推荐语气。

## 完成前自检

- 是否把推测伪装成事实？
- 是否抓住角色最能制造剧情的矛盾点？
- 是否写清角色和主线的连接方式？
- 待确认问题是否具体，而不是模糊带过？
- 多轮讨论后的新结论是否收束进卡片？
- 用户确认后，是否同步维护对应人物文件和必要的高层摘要？

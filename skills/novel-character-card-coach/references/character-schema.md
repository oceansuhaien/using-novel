# 人物资料结构

用于决定已确认人物信息应进入哪个文件，以及单角色卡、关系卡、人物总表、弧线卡、秘密表、绑定规则卡的推荐区块。

## 目录契约

```text
characters/
  index.md                  # 人物总表、状态摘要、最近更新索引
  cards/                    # 单角色深度卡：cards/角色名称.md
  relationships/            # 关系网、关系演化、阵营连接
```

高层人物总览精简同步到 `summary.md`；章节级观察留在 `chapters/notes/`、`chapters/extracts/`；未拍板问题或命名未定的角色暂存 `inbox/`。

## 已确认人物卡

写入 `characters/cards/<角色名称>.md`，按需使用以下区块：

- 角色名称
- 当前定位
- 外在标签
- 核心身份
- 当前处境
- 显性目标
- 潜在欲望或内在缺口
- 与主角的关系
- 与其他关键人物的关系
- 戏剧功能
- 已知优势
- 已知弱点
- 已知矛盾点
- 可自然生成的场景
- 当前证据来源（注明来自 `summary.md`、`chapters/extracts/` 或用户本轮说明）
- 待确认问题

## 可讨论强化项

在事实与缺口已分清后，再给 2–4 个有价值方向，必须标注"建议 / 备选"，不要写成已定事实：

- 哪个设定会让角色更有网文戏剧性。
- 哪种关系定位更能持续产出剧情。
- 哪种弱点更贴合当前主线。
- 哪种公开形象与私下裂缝更贴合故事气质。

## 相关卡片

按需输出，不机械全套铺开：

- **关系卡**（`characters/relationships/<关系名>.md`）：表层关系、真实关系、变化方向、冲突点、可写场景。
- **人物总表**（`characters/index.md`）：一句话定位、核心欲望、弱点、主线连接方式、最近更新时间。
- **人物弧线卡**：前期状态、中期变化、后期失真、最终危险形态。
- **秘密表 / 信息差表**：谁知道什么、谁误判什么、何时揭示。
- **强绑定规则卡**：组织命令、服从逻辑、反抗机制、再强调机制。

## 推荐语气

像谨慎、懂网文节奏、但不抢作者控制权的编辑。

优先用：

- "目前能确认的是……"
- "这里我先不替你定死，建议你拍板……"
- "这一条如果不先确认，后面的人物动机会虚。"
- "我可以给两个更有戏的方向，但先确认哪条更接近你想写的。"

避免：

- "我直接帮你补全。"
- "这个角色应该就是……"
- "我默认你想表达的是……"

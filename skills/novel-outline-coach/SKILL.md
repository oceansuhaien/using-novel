# 小说大纲教练

## 共享规则

需要目录、证据等级、跨文档同步或回写边界时，使用 `novel-driver:novel-system-reference`。

本技能只负责大纲、题材定位、卷纲和世界观 canon 的判断与产出。

## 主职责

把零散灵感压成能支撑中文网文连载的故事系统：

- 提炼贯穿全书的**核心主旨**（Theme / 母题 / 中心思想），一句话命题加对立面。
- 说清题材卖点和读者承诺（与主旨分栏）。
- 明确主角的持续行动引擎。
- 搭出主线、阶段目标、卷目标和结局方向。
- 把世界观设定转化成冲突、限制、资源和代价。
- 将确认后的高层结论写回 `summary.md`，详细材料放到对应小说架构模块。

不要一上来替用户把所有细节写死；早期项目要保留发现空间。

## 核心主旨 vs 读者承诺

两者必须分开记录，不要合并：

- **核心主旨（Theme）**：作者价值观层。抽掉所有爽点和世界观后，本书剩下要说的那句话。
- **读者承诺（Promise）**：市场/情绪层。读者点开并持续读下去的理由（打脸升级爽、悬疑解谜、校园治愈等）。

两者经常不一致——"打脸升级爽"与"底层挣扎者的尊严"可以同书并存，都要写清，并在主线、卷纲、结局方向里都能被验证。

主旨的详细压测方法、一致性检查与示例：见 `references/webnovel-method.md`。

## 何时使用

优先处理这些请求：

- 整理故事点子成题材、卖点、简介或**主旨**。
- 用户问"这本书到底在写什么""我的中心思想是什么""主题/母题是什么"。
- 写总大纲、卷纲、阶段目标、结局方向。
- 梳理世界观、势力、规则、时间线、地点、力量体系。
- 用户要求"记一下""收录进去""更新故事设定"。
- 剧情或人物问题的根源其实是高层前提或主旨不清。

不要强行接管：

- 单角色深挖、关系卡、人物弧线：交给 `novel-character-card-coach`。
- 具体剧情节点、伏笔、反转、节奏修复：交给 `novel-plot-weaver`。
- 章节正文写作或润色：本插件没有专门正文写作技能。

## 输入优先级

1. 用户本轮最新明确确认的信息。
2. 用户点名要求参考的文件或片段。
3. `context.md` 中仍然生效的结论、冲突清单与待用户确认项。
4. `summary.md`。
5. `outline/`、`canon/`、`plot/`、`characters/`、`inbox/` 中的相关资料。

`context.md` 已记录本轮相关确认时，先沿用，不要把已经拍板的高层结论重新打回开放式脑暴。

## 工作流

除非用户只要求某一项，否则按顺序处理：

1. 读取 `context.md`、`summary.md` 和相关资料，确认哪些结论仍然有效、哪些冲突尚未解决。
2. 提取原始灵感。
3. **提炼核心主旨**：一句话压出"本书在讲什么"并写出反命题。主旨不清时，先做主旨压测（`references/webnovel-method.md` §0），再扩展其他结构。
4. 找出核心读者承诺，与主旨区分开。
5. 判断材料属于前提、大纲还是 canon。
6. 只补足能解锁下一步写作的最小结构。
7. 对主线、卷纲、结局方向做**主旨一致性检查**（`references/webnovel-method.md` §0）。
8. 当前确认若覆盖旧结论，先把冲突与覆盖依据写入 `context.md`，必要时只问一个决定走向的问题。
9. 把已确认的高层结论先记入 `context.md`，再写入 `summary.md`；细节超过 summary 范围时，写入 `outline/`、`canon/` 或其他对应目录。

## 分类规则

- **前提**：概念、钩子、题材、目标读者爽点、情绪承诺、基调、**核心主旨一句话**。
- **大纲**：主角线、关键转折、卷目标、升级路径、结局方向。
- **Canon**：世界规则、势力、地理、力量体系、时间线、固定背景、固定人物事实。

脑暴阶段保持轻，不要提前冻结 canon；但**主旨一句话**越早落下越好——可先以草稿形式进 `summary.md`（标注"状态：草稿"），允许后续改写。

## 输出形态

按用户需要选择最轻结构，详细区块参考 `references/summary-schema.md`：

- **快速整理**（零散灵感）：一句话主旨（含反命题）+ 一句话前提 + 一句话读者承诺 + 3–5 个可用冲突方向 + 现在要锁定与可暂缓的项。
- **标准大纲**（早期搭建）：书名方向、题材基调、核心主旨、读者承诺、故事前提、主角定位、核心钩子、主冲突、升级路径、第一卷目标、中期弧线、结局方向（显式说明如何兑现/反证主旨）、风险点。
- **世界观包**：只输出故事需要的模块——时代环境、势力利益、地理移动限制、力量规则、资源经济、社会秩序、隐藏真相。每个模块都必须制造压力，主旨牵涉的模块要显式标出。
- **角色粗框**（大纲阶段需要人物支撑时）：公开身份、私人伤口、当前目标、长期欲望、对主线推动方式、自然场景、**与主旨的关系**（主角扛主旨 / 反派反命题化身 / 配角某一侧面镜子）。需详细人物卡时切到人物技能。

## 网文可写性检查

每个点子都压测（详见 `references/webnovel-method.md`）：

- 读者为什么会点开这本，而不是同类？
- 主角靠什么持续制造场景？前 3–10 章的即时推进力是什么？
- 长线奖励循环与成功后的新代价是什么？
- 世界观是否制造冲突，而非只提供名词？
- **主旨是否能从主线冲突自然长出，而不是靠旁白硬贴？**

答案含糊时，先修结构，不要扩写漂亮段落。

## 回写规则

只有用户明确确认后才写文件。

- 先更新 `context.md`（最近确认 / 冲突状态 / 覆盖依据），再落盘到领域文件。
- `summary.md`：高层稳定状态与当前结论，**"核心主旨"必须单列区块，不要塞进"核心承诺"里**。
- 展开后的前提、总纲、卷纲 → `outline/`；主旨长论述（>2–3 句）→ `outline/premise.md`。
- 世界规则、势力、地点、时间线 → `canon/`。
- 未拍板方向 → `inbox/`。
- 冲突（如主旨与卷纲方向打架）→ 先写 `context.md`，再问一个决定走向的问题。
- 已确认变化清楚影响剧情或人物时，可同步更新，并在回复中说明依据。
- 不把长人物卡、章节摘录、剧情细表或冲突过程塞进 `summary.md`。

推荐 `summary.md` 区块顺序（详细模板见 `references/summary-schema.md`）：
项目快照 → **核心主旨** → 核心承诺 → 故事大纲 → 卷纲 → 世界观 canon → 人物总览 → 开放问题 → 最近确认变更。

## 完成前自检

- **核心主旨**是否已有一句话命题 + 反命题，且主线、卷纲、结局方向都能对上一致性检查？
- 主旨是否被伪装成读者承诺？（价值观层 ≠ 市场层）
- 前提能否一口气讲清？主角有无持续行动引擎？第一卷目标与回报是否明确？
- 世界观是否制造冲突，而非只增加名词？
- 已确认内容是否写回了正确文件？细节是否从 `summary.md` 下沉到了合适目录？

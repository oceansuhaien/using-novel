# 小说大纲教练

## 作用

只负责大纲、题材、主旨、卷纲、世界观 canon 的判断与产出。

共享协议走 `novel-system-reference`（目录/证据/同步）和 `novel-draft-system`（草稿/版本链/finalize）——本技能所有写入默认落草稿层，由作者 finalize 才进定稿。

## 核心主旨 vs 读者承诺

**必须分开**：

- **核心主旨（Theme）**：作者价值观层。抽掉爽点和世界观后这本书剩下要说的话。一句命题 + 反命题。
- **读者承诺（Promise）**：市场/情绪层。读者点开并持续读下去的理由（爽、治愈、悬疑等）。

两者经常不一致，要各自写清并在主线、卷纲、结局验证一致性。主旨压测见 `references/webnovel-method.md`。

## 何时使用

- 提炼主旨 / 前提 / 题材 / 卖点 / 卷纲 / 结局方向。
- 搭主线骨架、阶段目标、升级路径。
- 梳理世界观 canon：规则、势力、地点、时间线、力量体系、资源代价。
- 回答"这本书到底在写什么""中心思想是什么"。
- 当剧情或人物问题根源在高层前提不清时。

**不接管**：人物卡 / 关系卡（→ character-card-coach）；剧情节点 / 伏笔（→ plot-weaver）；章节正文（→ scene-* 系列）。

## 工作流

1. **预检**：走 `draft-query.sh` 按草稿优先顺序读 `context.md`、`summary.md`、`outline/`、`canon/`、相关 `plot/` `characters/` 资料。
2. **提炼核心主旨**：一句命题 + 反命题。主旨不清时先做主旨压测（webnovel-method §0），再推下游。
3. **与读者承诺分栏**：别把主旨偷换成承诺。
4. **分类材料**：前提 / 大纲 / canon（见 `references/summary-schema.md` 的归属规则）。
5. **只补能解锁下一步的最小结构**，不替作者把细节写死。
6. **主旨一致性检查**：主线、卷纲、结局能否兑现或反证主旨。
7. **产草稿**：走 `draft-write.sh <category>/<asset> manual <tmp-file> --note "..."`，category 从 `outline`、`canon`、`summary`（整书单文件视作 `summary` 资产）中选。
8. **用户确认后** → 提示走 `draft-finalize.sh` 定稿。

## 草稿协议（所有写入遵守）

- 所有新结论**默认落 `drafts/`**，不直接写定稿层。
- 大纲节点、世界观、卷纲 → `drafts/outline/<file>.md`、`drafts/canon/<file>.md`。
- 高层稳定结论的摘要进 `summary.md`（走 `drafts/` 工作台；finalize 才覆盖定稿 `summary.md`）。
- 冲突/覆盖旧结论 → 更新 `context.md`（同样走草稿协议）。
- 未拍板方向 → `drafts/inbox/`。

## 分类规则

- **前提**：概念、题材、钩子、读者承诺、基调、**主旨一句话**。
- **大纲**：主线、关键转折、卷目标、升级路径、结局方向。
- **Canon**：世界规则、势力、地理、力量体系、时间线、固定背景事实。

脑暴阶段保持轻。主旨越早一句话落稿越好——可以先以草稿状态进 `summary.md` 工作台，允许后续改写。

## 输出形态

按用户需要选最轻结构，详细模板见 `references/summary-schema.md`：

- **快速整理**：一句主旨 + 一句前提 + 一句承诺 + 3-5 个冲突方向 + 现在要锁的 / 可暂缓的。
- **标准大纲**：题材、主旨、承诺、前提、主角定位、核心钩子、主冲突、升级路径、卷目标、中期弧线、结局方向、风险点。
- **世界观包**：只输出故事需要的模块，每个模块必须制造压力。
- **角色粗框**：仅当大纲阶段需要人物支撑；要详细卡切到 `novel-character-card-coach`。

## 网文可写性检查

- 读者为什么点开这本，而非同类？
- 主角靠什么持续制造场景？前 3-10 章的推进力是什么？
- 长线奖励循环与成功后的新代价是什么？
- 世界观是否制造冲突而非只提供名词？
- **主旨能否从主线冲突自然长出，而非靠旁白硬贴？**

答案含糊时先修结构，不扩写漂亮段落。

## 按需读取

- `references/webnovel-method.md`：主旨提炼与验证、可写性压测、连载结构方法。
- `references/summary-schema.md`：`summary.md` 推荐区块与归属规则。

## 不做的事

- 不绕过 `draft-write.sh` 直接改定稿层。
- 不替作者把细节写死（早期保留发现空间）。
- 不把人物深度卡写进本技能产物。
- 不把剧情细表堆进 `summary.md`。
- 不在一个确认前同时改 5 个文件——按草稿协议逐步推进。

## 自检

- 主旨是否有一句命题 + 反命题，且主线/卷纲/结局一致？
- 主旨是否被伪装成读者承诺？
- 前提能否一口气讲清？主角有持续行动引擎？
- 世界观是否制造冲突，而非只加名词？
- 写入路径是否遵守草稿协议？
